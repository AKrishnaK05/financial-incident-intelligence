# Architecture

## 1. Single computation path

`pipeline.py::run_pipeline()` is the single source of truth for the deterministic investigation computation.

```text
simulator generators
       ↓
settlement engine
       ↓
incident detector
       ↓
state graph
       ↓
evidence + timeline
       ↓
hypotheses + deterministic reasoning
       ↓
correlation + blast radius + exposure
       ↓
incident reports
       ↓
governance recommendations + approval requests
```

`simulator/main.py` does not reproduce this logic. It calls `run_pipeline()` and prints a narrated version of the result.

## 2. AI boundary

The AI layer is downstream of deterministic financial truth.

```text
IncidentReport
Evidence
TimelineFacts
Hypotheses
ReasoningAssessment
ActionRecommendation
        ↓
   AgentContext
        ↓
  InvestigationLLM
        ↓
 AgentOutput (Pydantic)
        ↓
InvestigationNarrative
        ↓
     Validator
```

The model never receives the full `FinancialStateGraph`. It receives only a curated `AgentContext`.

The deterministic reasoning trace is attached to the final narrative by the application, not generated by the model.

## 3. Provider separation

- `investigation/llm_interface.py` defines the provider contract.
- `investigation/agent_schema.py` defines the external JSON contract and converts it into the internal model.
- `investigation/investigation_models.py` contains application-level response objects.
- `investigation/providers/gemini_provider.py` contains Gemini-specific API code.
- `investigation/providers/openai_provider.py` contains the optional OpenAI implementation.
- `investigation/agent_adapter.py` provides a deterministic mock provider.
- `investigation/service.py` orchestrates one AI investigation and validation.

## 4. Governance boundary

The action policy produces bounded recommendations such as:

- `MANUAL_REVIEW`
- `REVIEW_AND_REPROCESS`
- `ESCALATE_INCIDENT`

Every recommendation requires human approval. No provider is allowed to change the action or execute financial remediation.

## 5. Evidence boundary

The prompt explicitly separates:

**Established facts**

- refund processed before cutoff;
- webhook delivered after cutoff;
- observed delay;
- refund record exists;
- observed financial variance.

**Unresolved questions**

- why the webhook was delayed;
- whether the underlying cause was infrastructure failure, queue backlog, retries, or another mechanism.

This allows the AI to express high confidence in the immediate failure mechanism without inventing a deeper infrastructure diagnosis.

## 6. Evaluation boundary

Ground truth is generated from controlled injections but is not supplied to the detector, hypothesis engine, reasoning engine, or AI agent.

The evaluator compares the independent outputs against ground truth after the run.

Current metrics:

- detection precision / recall / F1;
- aggregate exposure error;
- root-cause accuracy;
- systemic clustering accuracy.

AI-specific validation is performed separately because the AI's role is explanation rather than financial truth establishment.
